## 一句话

把 Qwen3.5-9B 的真实接线（φ）与真实权重（θ，取 Q4_K_M 量化版，见 D12）压成一根 25 × 25 × 80 mm K9 水晶柱里的立体雪花。
交付给厂家的是一份普通三维模型；爆点、点距、走刀全部由厂家决定。

## 五个词，不许混

| 词 | 含义 | 谁决定 |
|---|---|---|
| **体素** | 降采样后的灰度栅格；1 体素 = 该处 N 个权重的统计量 | 我们 |
| **雪花点** | 经真实权重特征提取与压缩形成的带灰度小几何块；等大小，暂不用大小编码数值；不是随机有／无点，也不是激光爆点 | 我们 |
| **爆点** | 激光在玻璃内部打出的微裂纹 | 厂家 |
| **几何** | OBJ 里的面与体 | 我们 |
| **灰度** | 每个小块携带的连续数值通道，内部可用 0–1；如何被厂家转成爆点、可分辨几档需另行核实 | 我们定义、厂家实现 |

**D2 点数是后验结果，不是限额。**（用户 2026-11-16 拍板：纯后验核对）

三层分开，不能混：

| 层 | 是什么 | 由谁决定 |
|---|---|---|
| 网格 | 一级切片时确定每块的三维格数；可手动指定合并力度，也可按块尺寸和点距自适应 | 一级切片输入；生成后不随 gumball 改变 |
| 灰度 | 每格的统计值经曲线映射后的连续灰度，不转成随机出点概率 | 真实权重和明确记录的映射参数 |
| 雪花点数 | 小块数，须区分候选格数、正灰度格数和屏幕显示数；不是爆点数 | 由网格与灰度映射确定；单纯重排不重算统计 |

- 总点数**没有预设值，也没有可以“用完”的预算**。它只是算出来的。
- 后验报告应报：灰度小块数、每格权重数、几何干涉、空间占用和灰度分布。厂家爆点数与机时只有取得加工规则后才可估计，不能把小块数除以打点速度当作机时；现有编辑器报告尚待按此口径迁移。
- **只报警，不改生成**。超过参考线就标红，提示去调 γ / 底噪地板 / 压缩倍数 / 毛坯，然后重新算一遍。参考线本身是报警阀值，不是配额；它的来源见 U12。
- 后验统计须区分整体平均、局部密度、实际近邻间距与点径；这些数可辅助核对工艺，不能仅凭一个百分比判断是否会裂。密度检查的空间范围、工艺参考值与来源需明确；未经厂家核实不声称安全。
- 屏幕上画多少个点是渲染抽样，与玻璃里实际多少个点无关，两者在界面上分开标。
- **作废的旧表述**：`墨水预算 = 栅格 × 填充上限`、“雪花用掉剩余预算”。这两条等于先定总数再分配，与自适应生成矛盾，已从代码和本文中删除。

**D3 框和包络面都是实体，粗细（毫米）和灰度都可调。**（用户拍板）
- 框：每个块的 12 条棱各是一根方梁，截面边长就是"框的粗细"。
- 包络面：每个块外面一层闭合薄壳，壳厚就是"包络面的厚度"。
- 为什么必须是实体：零厚度的面片和 OBJ 里的 `l` 线段，在切片软件里基本切不出点；另外 WebGL 的线条宽度在 Windows 上恒为 1 像素，用线条画的框在预览里也调不了粗细。做成有毫米截面的实体后，预览里看到的粗细就是导出的粗细。
- "透明度"就是灰度：玻璃里没有透明度，只有点的疏密。框和壳各有一个灰度滑块，预览里显示为透明度，成品里是点密度，不单独做"透明度"滑块。
- 2 倍点距只是过薄参考，显示提示，不强制作为厚度下限，也不凭这一条宣称一定会断裂；实际工艺需厂家核实。
- 历史量级估计（约300块、典型尺寸1.2 × 4 × 4 mm、点距0.08 mm；棱长和薄壳近似忽略角交集）：框截面0.3 mm时满密度约194万点，灰度15%约29万；壳厚0.16 mm时满密度约480万，灰度10%约48万。这不是现版370个实体的精确结果。
- 数字口径更正：默认长方体内参照20 × 20 × 75 mm对应约5856万候选位置，不是586万。上述量级占候选位置约3.3% / 0.5%、8.2% / 0.82%，不是旧文的33% / 5%、82% / 8%。候选位置不是配额，不给雪花扣点。
- 现版框和面的起始灰度取4.2的观感，几何与灰度可继续调整；未将这些显示初值当成加工安全推荐。
- 本条旧版写的"框只做骨架级，模块之间靠黑缝分隔"是我当时的收缩建议，已被用户的决定取代。整块可雕区外面要不要再包一层大框，是另一个问题，见 U4。

**D4 保留谱分解作为特征提取方法，不把它等同于有用／无用或训练前后分离。**
现有实验使用奇异值参照 `s₊ = σ(√m + √n)`，σ 暂取整张权重的均方根。它来自独立随机矩阵模型的尺度参照，不是测得的初始化噪声，也不是训练权重的通用知识阈值。用带幂迭代的随机化 SVD 估计前 K 个奇异值，超过参照的方向用于重构 `W_struct`，其余记为 `W_res = W − W_struct`。
项目没有已核实且与该次训练对齐的初始 checkpoint，不能据此声称 `W_struct = ΔW` 或 `W_res = W_initial`。少数谱模式也能在几乎每个位置都有值；能量比例不能推出空间上只有同样比例的小块。小样会比较全幅度、仅谱特征及弱残差合成，不提前决定残差去留。
实测（脚本 `scripts/compare_spectral_pooling.py`，图 `out/fig/spectral_vs_pooling.png`；BF16 权重，池化到 100×100）：

| 张量 | s₊ | 前几个奇异值 | 界外 k | 结构能量占比 | 池化图 CV（纯噪声理论 CV） |
|---|---|---|---|---|---|
| L0 mlp.down_proj 4096×12288 | 1.918 | 7.18 / 2.65 / 2.55 / 2.48 … | ≥ 15 | 1.99 % | 1.53 %（1.06 %，1.4 倍） |
| L3 self_attn.q_proj 8192×4096 | 2.861 | 13.60 / 6.96 / 6.71 / 6.27 … | ≥ 32（碰到上限 K=32） | ≥ 7.86 % | 16.20 %（1.30 %，12.4 倍） |
| 同形状同 σ 的纯随机高斯 | 1.918 | 1.76 / 1.75 / … | 0 | 0 | 1.06 %（1.06 %，1.0 倍） |

CV 是池化图的标准差除以均值；"纯噪声理论 CV"是同样每个体素平均那么多个独立高斯数时应有的波动。随机化 SVD 估出的奇异值不会超过真值（投影只会让奇异值变小），所以表里的 k 和能量占比都是下界。

图里看到的三件事：
- down_proj 池化后唯一看得见的结构（底部一整行偏亮）落在 `W_struct` 里，在 `W_res` 里消失了。这一类结构，谱能分出来。
- q_proj 的横带在 `W_res` 里几乎原样还在。它们是"某些行整体偏大或偏小"，不是低秩方向，谱分不出来，要靠行 / 列范数。
- 纯随机矩阵在谱上什么都没有，池化图在固定标尺下是一片均匀灰，这就是"实心雪花块"的样子。down_proj 的池化 CV 只有纯噪声的 1.4 倍，整体接近它；q_proj 是 12.4 倍，远离它。

**更正**：本条旧版写的"前 8 个奇异值 3.39 / 1.466 / …，只有第 0 个在界外，谱切不出有内容的图"是错的。当时 `scripts/test_quant_visibility.py` 的 step 6 用的随机化 SVD 没有做幂迭代，对衰减慢的谱严重低估（3.39 的真值至少是 7.18）。以这组数为前提的结论作废。

**D5 重排、一级切片、二级切片分开触发。**
- 日常交互：视角、显示、局部或全局 gumball、块深度与间隙调整，只重排已经生成的雪花，不重新做谱分解、池化或出点。
- 一级切片／统计重算：改变压缩或谱计算等统计生成设置才标需重算，用户按按钮执行。首次读取权重与建立缓存，后续复用条件须核实；不把池化小矩阵SVD耗时当成原始张量耗时。
- 输出灰度：匹配统计缓存上的窗口／曲线即时重映射，不重读权重或重跑SVD。工作预览可即时更新，保存新映射版本并引用源统计，旧结果不覆盖。缺少匹配缓存则明确待计算，不自动启动；用户已确认这一路与按钮统计任务分开。
- 二级切片：用户按导出按钮，把当前排布与既有雪花写成带时间戳的三维文件和清单；不在导出时偷偷改变雪花数据。

**D6 前端单文件 HTML + CDN three.js r128；后端是 Python CLI（uv + numpy + gguf）。**
不引入 node + 不引入打包器：本机没有 node，且 r160 之后 `build/three.min.js` 与 `examples/js/` 已被删除，踩过两次。r128 自带的 `OrbitControls.js` 与 `TransformControls.js`（用作 gumball）已确认在 CDN 上可取。
不引入 torch：只用到 numpy 的矩阵乘，不需要 2.5 GB 的运行时。
`gguf` 是 llama.cpp 官方的 Python 包（已确认 0.19.0 版自带 `quants.dequantize`，支持 Q4_K 与 Q6_K），用来把 Q4 文件里的 4 bit 编码解码成数值，见 D12。

**D7 预览与输出共用同一份灰度小块数据，不另起一个随机外观生成器。**
位置、尺寸、灰度及显式过滤规则须可追溯。屏幕曝光、遮挡或透明叠加只是观察方式，未经厂家标定不称为成品仿真；也不能说输出灰度仅是屏幕效果。

**D8 结构用几何，数据用灰度；几何件也带灰度，用灰度控制它们占多少点。**
框和壳是结构，形状来自布局；块内雪花是一级切片产生的数据。残差棒按新版 D11 删除。
两类东西分别统计点数，没有共同配额。结构件的点数可按体积、灰度与加工参数估算，雪花点数取已生成点集的实际数量；重排时雪花数量不变，不因框变粗而给雪花扣点。结构件实际如何转成厂家爆点仍待工艺核实。
如果导出走的是"几何 + 灰度贴图"路线（U1 乙），切片软件是否读灰度尚未验证，几何件实际切出多少点要靠测试件确认（U2）。

**D9 参数按作用分组，不许混在一个滑块里。**
- 外观：只影响屏幕，不进文件。相机、标签开关、"按功能着色"开关、设计视图 / 成品模拟视图切换。
- 排布：模型块的缩放 / 旋转 / 平移（gumball）、块深度、x/y 间隙、框截面和壳厚，进 manifest；不触发雪花一级切片。幽灵毛坯只作参照，不导出成作品，也不驱动模型大小。
- 雪花数据：合并压缩力度、谱提取设置等统计生成参数按按钮重算；匹配缓存上的窗口／曲线即时更新当前输出灰度，保存新映射版本，源统计和旧结果不覆盖。残差选择／合成若已有匹配缓存可重映射，缺少所需统计则明确待计算，不假称任意改变都无需重读。数值算法种子只作复现记录，不是作品随机疏密参数。
- 结构件灰度：框 / 壳的灰度，修改后更新结构件与后验报告，不重算雪花。
- 后验参考：密度参考线、主参照毛坯与打点速度只影响核对和耗时估计，不约束前置生成。
注意：本条旧版把"线框透明度"归为外观。现在框是实体，它的透明度就是灰度，会变成玻璃里的点，所以归为数据。

**D10 完整幅度、谱特征与行列强度分别保留，默认直接压缩完整权重，适用处可选谱，不强制合成。**
不同统计能显出不同性质：D4的样例中，某些共同模式可在谱重构中看见，某些幅度条带仍留在残差、完整幅度或通道强度中。不能据此要求所有块“纯谱＋行列合成”，也不能将单一特征强度称作功能重要性。本批独立新版默认完整幅度，提供原缓存的其他适用通道；不适用处提示直接幅度回退。未来合成须另定明确配方，不自动叠加。
残差是尚未由选定谱模式表达的真实权重部分，不是已证实无用的噪声。人为灰度地板只会强制弱位置也有正灰度，不等于保留真实信息；是否需要地板、残差是否加入及其权重均待小样观察，不再以“防止真空”默认要求保留。
独立首批已有可调窗口与多点曲线、默认完整幅度与其他缓存通道；新合成配方和最终作品默认值仍待确认，见U7，不将“未定成品方案”误说成“曲线未实现”。

**D12 权重来源：Qwen3.5-9B 的 Q4_K_M 量化版 GGUF。**（用户拍板，不追求原精度）
- 依据：U5 的实测，池化到体素尺度后 Q4 与 BF16 的差异在打点本身的随机波动以下。
- Q4_K_M 是一套混合配方的名字，不是每个张量都是 4 bit。实测这个文件用了 5 种格式：Q4_K（132 个）、Q6_K（22 个，含 lm_head 和一半的 ffn_down）、Q5_K（48 个）、Q8_0（48 个）、F32（177 个一维张量等）。每个张量的实际格式都要记进 manifest，铭牌上写 `Qwen3.5-9B · Q4_K_M`。明细见 `docs/qwen35_9b_facts.md` 第 3 节。
- "反量化"在这里只是解码：Q4 文件里每个权重存的是一个 0–15 的整数编号，再配一组每块共用的缩放系数；只有乘回去才得到能算 |w| 和 SVD 的数。解码出来的就是 Q4 的值，不会恢复 BF16 精度。
- GGUF 里的张量名与 HF safetensors 不同，对照表见 `docs/qwen35_9b_facts.md` 第 4 节。已用真实解码与 HF BF16 逐元素比对确认名字对应、维度方向、解码都正确（Q4_K 的 q_proj 相关系数 0.9973、误差 7.4 %；Q6_K 的 down_proj 相关系数 0.99983、误差 1.8 %）。
- GGUF 版**没有 MTP 头**（按张量数对账推出），见 U9。
- GGUF 与 HF 有三处数值约定不同：norm 权重加了 1；A_log 换成了 −exp(A_log)；线性注意力的 32 个 value 头被重新排序。见 U10。
- 文件（已选定）：`unsloth/Qwen3.5-9B-GGUF` 的 `Qwen3.5-9B-Q4_K_M.gguf`（5.68 GB，文本部分）与 `mmproj-BF16.gguf`（0.92 GB，视觉塔），下载到 `data/gguf/`，用 HF 记录的 sha256 校验（`scripts/download_gguf.py`）。同仓库还有 BF16 版，以后要对照时命名一致。备选来源：`lmstudio-community`（5.63 GB）、`bartowski`（6.17 GB）。
- 精度是混合的：文本部分是上面说的 5 种格式混合，视觉塔是 BF16。manifest 按张量记录。视觉塔是否进作品仍见 U3。

**D13 二维张量放进三维块的方式：注意力按头拆，MLP 与 embedding 按块的长宽比拆。**（用户拍板）
为什么要拆：权重在文件里是二维数表，每个数只有"第几行、第几列"两个坐标；玻璃里的块是三维的，每个位置需要三个坐标。把数表的一个轴拆成两个，就得到第三个坐标，每个数在块里恰好出现一次。
- 注意力（有结构依据）：把由"头数 × 每头维度"组成的那个轴拆开。
  - 全注意力层：`attn_q` 的 8192 行 = 16 个头 × 512（512 里一半是 Q、一半推断是输出门控，未核对代码），整张表变成 16 × 512 × 4096 的立方体。`attn_k` / `attn_v` 是 4 个 KV 头 × 256，`attn_output` 拆列（16 × 256）。
  - 线性注意力层（已由 GGUF 元数据与形状确认）：`attn_qkv` 的 8192 行是三段拼起来的——q 2048 行（16 个 key 头 × 128）、k 2048 行（16 × 128）、v 4096 行（32 个 value 头 × 128），先按段分开再按头拆。`attn_gate` 拆行（32 × 128），`ssm_out` 拆列（32 × 128），`ssm_alpha` / `ssm_beta` 本来就是每个 value 头一行。这些张量里 value 头的顺序被 llama.cpp 重排过，见 U10。
  - `attn_qkv` 三段保留各自语义和折叠规则，收录在输入投影功能块内；默认不为内部段额外画外框，与下方独立张量分区填充规则一致。
- MLP 与 embedding / lm_head（几何选择）：把长的那个轴（MLP 的 12288 个神经元、词表的 248320 个 token）分解成两个因子，因子按块的长宽比选。MLP 神经元的先后顺序本身没有含义（打乱顺序模型的计算结果不变），所以这一步不是结构依据。
- 一维张量（norm 的 γ、`A_log`、`dt_bias` 等）：没有谱，只做池化；把长度因式分解成小块。本来就是三维的张量（如 `conv1d`）按原形状。
- 不沿深度复制同一份数据：那样看起来也是三维，但同一个数会出现多次。
- 每个张量的原始形状、拆分因子、哪个轴对应块的哪个方向，都写进 manifest。
- **一个功能块含多个张量时，独立处理、分区填充。** 各矩阵按自身结构处理，小向量用对应统计；不把不同形状和作用的张量拼起来一起做谱分解。结果装进同一块的不同子区域，外面只画一套框。小张量也参与计算，子区域边界和张量归属写进清单。整块变形时这些区域和既有雪花一起伸缩，不重算一级切片。（用户已接受，编辑器规格 Q10）
- 已知的巧合：real_config 布局里每层块的厚度约 1.2 mm，0.08 mm 点距下约 15 层格子，和 16 个头接近，可以考虑一个头占一层。未定，留到布局阶段看效果。

**D14 编辑器：可编辑排布、按钮触发两级切片、纯后验核对。**（用户已明确；11-18 对草案其余明确推荐暂予接受）

排布与雪花参数在一级切片前都能自由调，不规定必须先把包络体积装进毛坯。一级切片后，块移动、拉伸、压扁只改变已有中心点的空间映射，源统计、格数不变，小块保持固定毫米尺寸，物理间距与检查更新。窗口／曲线在匹配统计缓存上即时重映射输出灰度，不重读权重或重跑SVD；保存新映射版本，不覆盖旧结果。压缩或谱计算等统计生成设置改变才标统计需重算，按按钮执行；缺缓存不偷偷启动计算。

|---|---|---|---|---|---|---|---|---|
| L0 ffn_down | Q6_K | 0.041 | 0.034 | 1.2 | 1 | 1.6 % | 2.06 | 1.01 |
| L3 attn_q | Q4_K | 0.184 | 0.042 | 4.4 | 7 | 32.9 % | 1.45 | 1.07 |
| L0 attn_qkv | Q5_K | 0.112 | 0.042 | 2.7 | 7 | 16.9 % | 1.42 | 1.03 |

> "纯噪声 CV"指同格子数、同均值的随机数组，每格 n 个样本取均值后的 CV = 0.5708/√n。表中的 CV 都是对 abs（绝对值）池化图算的。

**3. 谱分解不是万能的。** 在 attn 类块上它有 7 个界外奇异方向（能量 17–33 %）；在 ffn_down 上只有 1 个，而且就是全图均值（把非负的 |w| 图做谱分解，常数项必然是最大方向）。另外，signed 池化图的逐格均值与纯噪声的比值几乎正好是 1（0.0457 对 0.0456），说明和/列方向的逐格均值里没有低秩结构。

**4. 这些块的变化主要在"行"，不在"列"。** 三个块的行范数 max/中位都是 1.4–2.1，列范数都是 1.01–1.07。换成布局的语言：块的长轴（z，20 mm）对应列方向，而列方向几乎是平的；横带都在 (x, y) 平面上。

**5. attn_q 的横带是真的，不是量化造成的。** BF16 和 Q4_K 的池化图肉眼几乎无法区分，差值图是均匀噪声。横带间距量级与 8192 行 / 418 组的 8 个头分组有关，具体对应关系未核对。

**阶段 2 待定。**
- 灰度主源用什么：目前测了五种（|w| 均值、signed 均值、行范数×列范数、|w| 减外积的残差、前两种合成）。signed 是纯噪声；外积太光滑，会把横带抹掉；|w| 均值最直接可读。倾向用 |w| 均值，但未拍板。
- 块的网格尺寸：试算时借用 19 × 22 × 250（即 L28.v 那个块的格子数），ffn_down / attn_q 的实际块宽不同，要对齐得先拿到编辑器导出的 `layout.json`。
